# 三端演示动线

建议用 5–8 分钟展示「顾客点餐 → 商户出餐 → 平台管理」。三个标签页同时打开，能直接看到同一笔订单在不同角色中的变化。

## 演示准备

按[快速启动](../README.md#快速启动)运行 MySQL 与四个服务，打开：

- 顾客端：`http://localhost:3000`
- 商户端：`http://localhost:3001`
- 管理端：`http://localhost:3002`

顾客端可使用浏览器移动设备模式；商户端与管理端适合较宽窗口。演示商户登录码为 `HI888`、`COOL99`、`SEA666`，统一演示密码为 `demo-merchant-123`。管理员以 `.env.local` 中设置的账号登录。

先进入商户端，确认目标店铺在营业、商品没有售罄。页面会按营业时间显示打烊状态，演示时间不在营业时段时，可在店铺设置里调整本地演示数据。

## 1. 顾客：从摊位进入菜单

1. 在首页输入一个摊位码，例如 `HI888`，进入对应店铺。
2. 查看菜单分类、商品卡片和店铺详情，选择带规格的商品。
3. 切换份量或加料，观察价格变化，加入购物车。
4. 回到首页进入另一家摊位，再加一件商品，观察购物车按店铺分组。

这里展示的是围绕实体摊位组织的点餐入口，以及商品规格与购物车的交互。

## 2. 顾客：创建自提订单

1. 进入结算，选择「门店自提 / 堂食」。
2. 填写仅用于本地演示的联系电话，可补充口味备注。
3. 提交订单，查看按商户生成的订单与取餐信息。
4. 在订单付款界面点击「我已支付」，进入等待商户确认状态。

演示数据库不需要真实转账。这里的付款按钮仅推进演示订单状态，不能证明资金到账。没有配置商户收款码时，页面会显示相应提示；可继续展示订单状态与商户处理流程。

优惠券属于原型展示，主流程演示请保持未选择。海滩配送尚未开放，可展示其提示与配送意愿入口，不要作为已完成配送功能演示。

## 3. 商户：收款确认、出餐与核销

1. 在商户端登录刚刚下单的摊位，进入订单处理。
2. 找到待确认订单，核对商品、规格、备注和金额。
3. 点击「确认收款」，订单进入制作中。
4. 点击「制作完成，通知取餐」，顾客端显示待取餐状态。
5. 在订单详情点击「核销订单」并确认，完成订单；具备摄像头条件时也可演示扫码核销。
6. 回到顾客端查看完成状态，再看商户端经营统计。

订单通过 HTTP 定时刷新，切换后可能需要等待几秒。若购物车包含多家商户，需要分别登录对应商户处理各自订单。

## 4. 商户与管理员：展示可维护性

商户端可继续演示修改商品名称或价格、设置某个规格售罄，以及店铺营业状态。回到顾客端刷新，查看相应变化。

管理员端可展示商户列表、平台统计与设置页。创建一个演示商户后，使用返回的摊位码登录商户端；或切换一个店铺信息展示开关，再到顾客端刷新确认。

## 可选演示

| 功能 | 条件与说明 |
| --- | --- |
| 图片与凭证上传 | 配置 `RAINYUN_*`；使用演示素材，不使用真实收款凭证 |
| AI 海岛提示 | 配置 `GEMINI_API_KEY`；生成内容受网络与服务可用性影响 |
| 扫码核销 | 允许摄像头访问；本机可使用 localhost，远程访问通常需 HTTPS |
| 进店二维码 | 管理端生成；二维码基础地址需指向接收设备能访问的顾客端地址 |

## 常见情况

| 现象 | 检查方式 |
| --- | --- |
| 首页加载失败 | 确认 API 健康检查可访问，MySQL 已就绪，`api/.env.local` 的连接配置正确 |
| 登录信息与示例不一致 | 种子只在空表时创建；已有数据库保留之前的账号 |
| 商品无法下单 | 检查营业时段、营业开关、售罄标记与剩余库存 |
| 图片或字体不显示 | 部分资源来自外部服务，需联网；详见[素材说明](third-party-assets.md) |
| 上传报 OSS 配置缺失 | 对象存储没有配置；基础点餐无需上传即可演示 |
| 其他浏览器看不到顾客订单 | 顾客标识保存在当前浏览器，尚未提供跨设备账号同步 |

如需录屏或截图，优先展示顾客首页、商品规格、订单进度、商户订单工作台和管理端商户列表。项目中的示例商户、图片与统计应作为演示内容介绍。
